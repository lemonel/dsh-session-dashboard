## 1. 产品定位

**以项目组织工作，以会话（session）作为执行和管理的基本单位。**

用户先创建项目、设置公共标签和需要的自定义状态，再把已有或之后在 DSH 中创建的会话加入项目。项目内按会话分别跟踪工作状态、真实执行情况和人工验收；跨项目保留统一的待验收与需我操作入口。

本插件管理工作组织与进度，不替代 DSH 聊天、Agent 执行、工作区或权限管理。项目不是文件目录；跨工作区的会话可以属于同一项目。会话被放进项目，不意味着复制聊天、创建新 Agent 或开始执行。

### 希望解决的问题

- 可以先规划项目，不必先加入一批会话才能建立结构。
- 能从原生左侧会话列表直接发起加入项目，减少在另一份列表中重复查找。
- 项目公共标签不再需要逐个会话重复设置。
- 调研、开发、交付等工作安排可以由用户命名；每个安排都可能包含一轮或多轮 AI 执行。
- AI 本轮正常结束、用户验收通过、进入下一工作状态是不同的事情。
- 验收后由用户自由决定下一状态，而不是被预设流程推着走。

## 2. 决策与适用范围

### 2.1 已明确的产品方向

| 编号 | 方向 | 含义 |
| --- | --- | --- |
| D01 | 项目是主要组织入口，会话是管理粒度 | 先有项目也能使用；项目内各会话独立推进，不整体同步状态 |
| D02 | 项目关联一组非状态标签 | 公共分类与状态分开；项目不能向所有会话继承同一个当前状态 |
| D03 | 从左侧会话列表加入项目是目标操作 | 保留按钮等价操作，拖动不是唯一入口；具体宿主适配见第 7 节 |
| D04 | 状态允许“自定义状态 → 内置执行与验收 → 自定义状态” | 同一会话可重复进入执行过程；此规则只针对状态标签 |
| D05 | 下一状态由用户自由选择 | 不要求配置固定后继，不按列顺序推进，不自动应用上次选择 |
| D06 | 验收针对当时核对的执行轮次 | 阶段成果通过，不等于会话全部工作或整个项目完成 |

### 2.2 本次已采用的推荐设计基线

下列项目最初作为推荐设计提出，与上节 D01–D06 的产品方向保留来源区别。**本次用户授权后，R01–R06 已作为 `0.3.0` 的实现基线采用。** 采用不等于验收通过；若后续改变方案，须先更新本文及相应验收项。

| 编号 | 推荐基线 | 选择原因或影响 |
| --- | --- | --- |
| R01 | 明确加入项目，而不是按标签自动收录；一个会话最多属于一个项目 | 保留已有归属关系；标签相同不会使会话自动加入、离开或同时进入多个项目 |
| R02 | 项目公共标签动态展示，不复制成会话自己的标签 | 改项目标签或移动会话时，能够区分公共标签与个人添加的标签 |
| R03 | 自定义状态由各项目管理，使用稳定身份；另有“未设置状态”显示位置 | 项目可以有不同安排；同名状态不代表同一个状态，不强制创建调研、开发等模板 |
| R04 | 支持“验收并选择状态”和“仅验收，稍后选择” | 允许一次完成，也不强迫用户在验收时决定下一步；取消不产生半完成操作 |
| R05 | 跨项目移动保留本轮来源；没有执行过程时显式选择目标状态或未设置 | 保持已有移动能力，不伪造新阶段，不把同名状态自动对应 |
| R06 | 当前宿主优先采用原生会话行内的专用按钮兼拖动入口 | 避免整行拖动附带侧栏重排；实际浏览器与版本兼容验证通过后才交付 |

本期不增加项目级默认状态或默认优先级；这一选项不在本轮已确认需求内。

## 3. 与上一版的区别

| 内容 | 上一版 `0.2.2` | 本轮 `0.3.0` 实现范围 |
| --- | --- | --- |
| 主流程 | 添加会话，再进行分类和分组 | 创建项目，再新建会话或从左侧加入，在项目中管理 |
| 项目 | 名称、颜色、单项目归属；可建空项目但入口较深 | 明显的创建入口、公共标签、状态设置、成员与进度汇总 |
| 普通标签 | 仅直接设置在会话上 | 区分项目公共标签和会话自身标签 |
| 状态 | 全局固定进行中、待验收、已验收 | 自定义状态与同一套内置执行/验收过程配合 |
| 验收后 | 停在已验收 | 保留本轮验收记录，由用户自由选择去向或稍后选择 |
| 拖入 | 插件候选面板 → 项目列；卡片 → 项目列 | 仅原生侧栏专用入口：点击或拖到项目卡/项目内落点；仪表板不再有候选面板 |
| 全局入口 | 看板、待验收、归档；需我操作筛选 | 项目总览为主，同时保留跨项目的待验收、需我操作、未归属和归档 |

“已验收”从看起来的工作终点，调整为**一轮执行的人工决定及可暂留位置**。原有验收记录不能因此被删除或改写。

## 4. 项目、会话与标签

### 4.1 项目

项目至少包含名称、可选颜色、公共标签、可用的自定义状态及显示顺序。没有会话时也必须显示，可以直接接收添加。

- 创建项目不导入全部宿主会话，不自动创建聊天或启动 Agent。
- 项目显示成员数量、待验收数量和需我操作数量；这些数量按唯一会话计算。
- 项目没有一个会被成员统一继承的“当前状态”。成员状态汇总也不能自动宣布项目完成。
- 项目可删除：删除只清除项目这一分组概念（名称、颜色、公共标签、自定义状态与成员归属），其中的会话变为未归属并继续留在看板，会话主位置回到未设置；宿主聊天、历史与执行事实不受影响。不扩展级联删除、批量归档、成员权限或项目层级。
- 未归属会话保留独立入口；没有选择项目不意味着丢失数据。

### 4.2 会话

在同一个 profile 内，一个 session 仍只有一份仪表板记录。多处展示是同一记录的引用，不能重复计算或复制验收记录。

会话行支持只读对话预览：只读取当前或已持久日志中的用户、助手与工具内容，不发送消息、不启动或恢复 Agent，也不替代进入会话。

会话保存自己的标题覆盖、进展、普通标签、关联、项目归属及工作状态信息。项目变化不改工作区、不启动执行，也不覆盖已保存的手工进展和人工决定。

### 4.3 普通标签与标签来源

按 R02，用户在会话上看到的普通标签是“项目公共标签 + 会话自身标签”的去重结果，并能查看来源。

- 同一标签同时来自项目和会话时，只显示一次，但两种来源都保留。
- 删除项目中的某个公共标签，不删除会话自己添加的同一标签。
- 移到另一个项目后，改用目标项目的公共标签；会话自己的标签不变。
- 会话详情不能通过取消一个复选框，偷偷修改整个项目的公共标签；应引导到项目编辑。
- 普通标签不触发执行、验收或状态流转；普通标签列的拖动不在本期范围内。
- 旧的「优先级」维度已在 0.6.0 并入工作状态：不再有独立的优先级列表、筛选、分组或设置入口。
- 新界面的标签筛选覆盖展示的合并结果，并区分标签来源；现有自动化/API 中旧标签字段的含义不随之暗改，见第 10 节。

### 4.4 状态显示与「需我操作」

- 「需我操作」不是存储状态，而是从运行事实派生的注意力层（等输入、等授权、需恢复、失败、中断、同步异常）；它与状态正交，可以出现在任何状态上，也不改动卡片保存的状态。
- 界面上始终显示卡片真实状态（含自定义状态名和「未设置状态」），「需我操作」只作为状态旁边的一个小标记，并在悬停/读屏文本中说明具体原因，不替换状态文本。标记文字直接来自系统的 `turn/end` 结束原因：中断、失败、手动停止、目标受阻；系统没有给出结束原因（未闭合执行）时不显示这些结论，也不由插件猜测。
- 项目卡里的运行中会话显示“已运行 mm:ss”（本轮开始时间起算，等待输入/授权与冷快照不显示）；
- 完成通知只在会话主 Agent 的一轮结果真正结算时弹出：主轮次结束但仍有子 Agent 运行时保持安静，等看板结算（待确认/待验收、无运行中子 Agent）后弹一次；子 Agent 的完成不单独通知，已归档会话不通知。
- 状态颜色只有一套映射：进行中 info 蓝、待确认 info 蓝（与进行中有意同色，运行中用动态转圈区分）、待验收 warn 黄、已验收 ok 绿；自定义状态用它自己的颜色、没有颜色时用弱色，未设置用弱色。注意力标记用 danger 色。状态标签、状态下拉选项和看板列头共用这套映射。
- 系统给出终端异常结果（中断、失败、手动停止）且卡片仍是内置「进行中」时，状态标签直接显示系统结论（已中断/失败/已停止）并改用 danger 色，不再同时显示「进行中」；这只是显示派生，存储状态仍是进行中、位置不变，状态下拉与验收/归档规则也不变。

## 5. 主要使用流程

### 5.1 先建立项目，再放入会话

1. 打开仪表板的项目总览，点击“新建项目”。
2. 输入名称，设置所需公共标签；自定义状态可立即创建，也可稍后设置。
3. 创建后保留空项目，不要求必须选中会话。
4. 从左侧原生会话行的插件入口拖入，或点击“加入项目”选择目标。
5. 未纳入会话创建一份仪表板记录；已有会话按移动规则处理，不重复创建。
6. 进入项目看板，查看和调整各会话的状态。

### 5.2 调研与开发只是一个使用例子

```text
项目：支付系统改造
公共标签：客户 A、后端、第二阶段
自定义状态：待调研、待开发、待交付、暂缓

会话：接口方案
待调研
  → 用户在 DSH 实际发起执行
  → 进行中（来源状态：待调研）
  → 本轮正常结束
  → 待验收（来源状态：待调研）
  → 用户验收通过，自由选择“待开发”
  → 待开发
  → 再次实际执行，进入新一轮内置过程
```

验收后也可以选择“待调研”继续准备、选择“暂缓”，或仅验收并稍后决定。例子不规定必须从调研到开发，不根据状态名称推导含义。

### 5.3 自由选择下一状态

验收对话框展示会话、本轮来源状态、当前执行轮次和核对提示。状态选项来自**会话当前项目可用的自定义状态**，系统不预选下一项。若用户明确拖向某个自定义状态，该落点可作为本次选择带入对话框，仍须核对和确认，不能直接提交。

- 用户可以选原状态或其他可用状态，不要求相邻，不检查所谓“前进方向”。
- “验收通过并转入…”需要明确选择目标并确认；没有选择时不能偷偷采用第一列或上次结果。
- 按 R04，另提供“仅验收，稍后选择”，停在内置已验收位置。
- 自由选择的是下一工作状态，不是任意把执行事实改成成功。
- 选择状态不发送消息、不启动/恢复 Agent、不解除问题或授权等待。
- 之后继续选择或修改自定义状态，不生成新的验收记录。

## 6. 状态标签的规则

### 6.1 一张卡片，一个主状态，保留执行来源

自定义状态与普通标签是不同的数据。卡片在看板中只有一个主状态位置；内置执行过程发生时，需要保留它来自哪个自定义状态。

| 信息 | 产品含义 |
| --- | --- |
| 自定义状态 | 用户安排当前工作的位置，例如待调研、待交付、暂缓；名称不触发特殊行为 |
| 本轮来源 | 执行被可靠识别时对应的项目、自定义状态及当时名称；用来解释这一轮在处理什么 |
| 内置状态 | 进行中、待验收、已验收；受宿主执行事实和人工决定约束 |
| 运行详情 | 正在执行、等待回答、等待授权、暂停、失败、中断、待继续、同步异常等真实情况 |
| 人工记录 | 已认证用户作出的决定、针对哪一轮、何时发生及所选去向；宿主未提供可验证的个人身份时，不伪造姓名或账号归属 |

“阶段”只是对本轮来源的说明，不另设一套要求用户维护的阶段实体。界面不得把用户的“待调研”自动改写成“调研”并当作另一个状态。

推荐卡片显示“待验收 · 来源：待调研”。“进行中”不等于 Agent 此刻正在运行，等待、失败或待继续等情况必须清楚显示，不能一律显示运行中。

### 6.2 进入和离开内置过程

| 当前情况 | 事件或用户操作 | 结果 |
| --- | --- | --- |
| 可靠确认没有实际轮次且没有待处理执行 | 用户选择自定义状态 | 可从未设置位置或旧版“进行中 / 尚未执行”展示进入所选状态，不要求虚构一次执行或验收 |
| 自定义状态或未设置状态 | 在 DSH 发生真实新执行 | 进入进行中，记录本轮来源；不要求从插件启动 |
| 已在内置过程 | 发生真实新执行 | 当前处理切换到新轮，旧核对失效；保留旧记录，不复用旧验收 |
| 进行中 | 本轮完整正常结束 | 进入待验收；不得直接进入某个自定义状态 |
| 进行中 | 等待、暂停、阻塞、失败或中断 | 保留来源与真实原因，不当作完成，不自动推进 |
| 待验收 | 通过并选择自定义状态 | 原子保存本轮验收和去向，进入所选状态 |
| 待验收 | 仅验收 | 保存本轮验收，停在已验收，等待用户选择 |
| 待验收 | 明确退回 | 保留未通过/退回事实，回到进行中并显示待继续；不启动 AI |
| 已验收 | 自由选择自定义状态 | 保留既有验收记录，进入所选状态，不再次验收 |
| 自定义状态 | 用户切换到另一自定义状态 | 保存人工调整，不伪造执行或验收 |

已在内置过程时，如来源仍适用于当前项目，新的实际执行继续保留该来源；这是继续处理同一工作安排，不是自动选择下一状态。没有可靠来源、在加入仪表板前已执行、或跨项目后未确定新来源时，显示“来源状态未指定”，不根据标题、聊天内容、同名标签或最新配置倒推。延迟同步或停机后发现执行时，只有能够可靠对应执行开始时的状态才绑定来源；不能拿同步时的最新状态回填过去。

### 6.3 必须保留的限制

- 不允许靠拖动或编辑把卡片直接设置为正在执行或待验收。
- 待验收不能靠普通移列悄悄变成已通过；拖向自定义状态时应打开验收并选去向的流程，而非直接写状态。
- 已有实际执行及异常未解决的内置过程不能通过普通移列隐藏。可靠确认尚未执行且没有待处理输入的会话，不仅因旧版显示为进行中就被锁住，可按上表选择初始自定义状态。其他情况可去原会话处理；如未来加入“放弃本轮”等动作，须单独设计，不能把它当验收通过。
- 退回不等于阻止返工；再次真实执行后按新一轮处理。暂停、停止、取消都不代表成果通过。
- AI 回复结束、工具完成或 Agent idle 不是充分完成依据；Goal 续跑间隙也不是阶段完成。
- 验收必须检查当前实际会话、执行轮次、运行状态及本次来源/成员/项目选择是否仍有效；新轮、移出重加或并发变化使旧对话框失效。
- 冷历史记录可以展示，但沿用现有安全边界：无法可靠核对当前执行状态时，不允许提交验收。
- 同轮迟到或重复的结束通知，不能把已经转入自定义状态的会话拉回待验收。
- 仅改普通标签、排列或状态名称，不能制造新执行轮次或新验收。
- 自定义状态即使名为“完成”，也不等于系统记录的人工验收。内置状态须有清楚的固定样式；自定义状态不得冒用其保留名称或身份。

### 6.4 保存、取消和冲突

- “验收通过并转入…”是一次用户操作：验收记录和去向一并成功或一并失败。
- 取消确认、来源失效或目标状态不可用时，不提交其中一半；保留选择和说明供重新核对，不自动改成其他目标。
- “仅验收”成功后再关闭状态选择，不回滚已经提交的验收，仍显示已验收。
- 多窗口编辑、拖动期间新执行、状态停用或项目移动均需在提交时复核。失败时不能先显示成功再静默回退。
- 状态选择和来源版本必须参与检查，不能只沿用旧版卡片元数据版本而漏掉新引入的变化。

### 6.5 管理自定义状态

按 R03，每个项目可创建、改名、设色、排序和停用自定义状态。显示顺序不是流转顺序。

- 不要求定义默认起点或下一状态；未选择时有“未设置状态”显示位置，它不是自动创建的业务标签。
- 停用后不能作为新去向，但已有成员、来源和历史记录仍显示，不自动迁移或隐藏；用户可以把停用状态中的卡片移到其他可用自定义状态。
- 已被引用的状态不能硬删除；本期不做合并、跨项目全局状态库或自动批量改状态。
- 改名不改变身份，历史显示当时名称；停用/改名不让旧执行变成新阶段，也不撤销已验收事实。
- 未归属会话保留内置状态管理和未指定来源；按本期基线，须先加入项目才能选择该项目的自定义状态。

## 7. 加入项目、移动与拖放

### 7.1 两种拖放必须分开

| 动作 | 改变什么 | 不改变什么 |
| --- | --- | --- |
| 拖到项目卡片、项目标题或“加入本项目”区域 | 项目成员关系；按 R02 更新公共标签的展示来源 | 不设置验收结果，不启动 AI，不覆盖自身标签、手工进展 |
| 在项目内拖到自定义状态列 | 发起状态切换，必要时打开验收确认 | 不把落点当作已执行、已结束或已通过的证据 |

来自侧栏、尚未纳入的会话不能通过落在某个状态列，直接被初始化为已验收或为过去执行补造阶段。添加与状态操作在交互和校验上必须分清。

### 7.2 原生左侧会话入口

当前对 DSH `0.2.0-rc.2` 的只读调研显示：普通会话行原生拖动使用 `text/plain` 传输 ID，用于宿主排序；拖动结束时仍可能提交最后经过的排序位置。它不是经过确认的跨插件 Session 拖放协议，接收落点不能保证消除源侧排序副作用。

按已采用的 R06，本期通过公开的 `sidebar.workspaces.session.row.action` 和 `sidebar.workspaces.session.menu.item` 添加插件自己的按钮/菜单项：

- 按钮可点击选择项目，也可从该按钮拖到项目。
- 插件只处理自己组件的拖动事件，不启动父行的原生排序，不监听或改写宿主私有 DOM。
- 传输内容使用明确的插件格式；ID 或 MIME 不是权限证明，落下后仍由后端核对当前会话、profile 范围、成员和版本。
- 不再保留仪表板内的「添加会话」或候选面板作为备用入口：已有会话只能从原生侧栏专用入口点击或拖入；缺少公开侧栏入口的版本不提供仪表板内加入已有会话的入口。窄屏、折叠侧栏等场景不能假装具备相同拖动能力。
- 整行原生拖动不是本期默认保证。后续若宿主提供可验证的正式协议，再评估接入，不通过全局事件拦截或宿主修改强行实现。

以上是当前版本的可行性判断，不是浏览器验收，也不能据现有八版本支持列表推断新拖放功能全部兼容。

### 7.3 成员处理规则

- 新会话：成功后只有一份卡片。默认不做历史验收；按可靠运行信息展示，不补造加入前的阶段。可靠确认无实际轮次且无待处理执行时，初始显示未设置状态，可再由用户选择；未知不能等同于尚未执行。
- 已在同一项目：提示已加入并可定位，不重复创建，不覆盖状态或字段。
- 已在其他项目：明确提示从哪里移到哪里；按 R05 处理状态差异，确认后提交。
- 看板已归档：先提示显式恢复；拖入不能静默恢复。
- DSH 已归档：沿用现有添加入口的显式选择规则；加入不取消宿主归档，不运行 Agent。归档信息未知时明确提示，不能按未归档放行受限制操作。
- 会话不存在、不可访问、已移出重加、项目失效或来源版本改变：拒绝旧操作，保留原数据并说明如何重新选择。
- 加入后被当前筛选隐藏：显示成功及隐藏原因，提供定位入口，不偷偷清空筛选。
- 松手在无效区域或取消拖动：没有成员、状态或原生侧栏排序写入。

### 7.4 跨项目的状态归属

按 R05：

- 没有内置执行过程需要处理时，跨项目移动要显式选择目标项目状态，或明确选择未设置；不按同名自动对应。
- 正在执行、待验收、已验收暂留或退回待继续时，可以改变项目归属，但本轮来源仍保留原项目和原状态，并清楚展示。
- 此时移动不完成验收、不改变当前内置状态。之后验收选去向使用当前项目的可用状态；旧确认必须重新核对。
- 下一次新执行若还没有目标项目内的明确来源，记为未指定，不能把原项目状态冒充为目标项目状态。
- 过去的执行和验收记录始终保留原来源；项目改名、移动、标签调整都不能改写它们。

## 8. 页面组织

```text
DSH 原生侧栏                 仪表板主区域
会话列表 + 加入项目入口       项目总览 / 待我验收 / 需我操作 / 未归属 / 归档
                            ├─ 新建项目
                            ├─ 项目卡片：名称、公共标签、会话与待处理数量
                            └─ 进入项目
                               ├─ 项目名称、公共标签、编辑项目、新建会话
                               ├─ 自定义状态与内置状态分区的看板
                               └─ 会话详情：进展、标签来源、执行与验收记录
```

- 项目总览是新使用流程的首页；老用户保存的入口/筛选尽量保留，提供明确返回项目总览的操作，不因升级丢失定位。
- 项目内默认按状态查看，也能按普通标签查看；切换展示方式不改变成员和状态。项目卡里的会话列表与看板每一列内部都按配置的状态顺序排列，同一状态内活动时间最新的会话排最上面，活动更新会实时重排。
- 自定义状态区与内置执行/验收区视觉上分清，但不能把内置列放成唯一的流程终点。卡片在主状态看板只出现一次。
- 标签视图可以出现同一卡片的多处引用，总数量仍去重。
- 全局待验收和需我操作不受当前项目筛选影响；两个数量独立，不把失败或待回答混成待验收。
- 全局汇总不同项目的自定义状态时，保留项目限定，不将同名状态合并为同一状态。
- 空项目、无会话、筛选无匹配、加载失败分别展示；错误不伪装成空项目。
- 所有拖动都有按钮/键盘等价操作，触屏不依赖悬停；操作后保留可理解的焦点和定位。
- 新功能及修改到的既有界面须按宿主语言提供 zh/en，用户原始项目名、状态名和标签不自动翻译。

## 9. 记录与可靠性

本期需要保存本轮来源、用户状态调整和人工验收/退回及去向记录；详情能说明“哪轮在什么状态下执行、用户如何处理、之后去了哪里”。只记录业务所需信息，不复制聊天正文。

- 记录使用稳定身份，不以名称、列位置或当前展示状态代替执行轮次。
- 来源和人工决定按当时事实保存；新一轮替换当前展示，不删除旧的人工决定。
- 新增持久历史的保留与容量策略须在技术设计中明确，不能依赖现有可过期的扩展事件流冒充永久历史，也不无界增长。
- 重复请求不重复创建成员、验收或流转记录；重试不能把旧去向应用到新轮。
- 认证、取消、来源复核、多窗口冲突及提交前检查不因项目中心改版而放宽。
- 页面关闭不停止后台同步；重载、禁用、卸载后清理资源，旧页面和旧请求不能回写新实例。
- 看板归档继续仅改变日常可见性，不停止 AI，也不等于 DSH 会话归档或项目完成。

## 10. 旧数据、公开接口与自动化

### 10.1 升级

- 保留已有项目身份、会话归属、普通标签、标题/进展、关联、归档、执行轮次、人工决定及时间。
- 旧版本的每个优先级按名称并入自定义状态：同名并入已有状态，新名称成为新的自定义状态；旧优先级列表、筛选、分组与卡片上的优先级字段在升级后清除，不静默放宽筛选。
- 旧项目的公共标签默认为空；原有会话标签仍是会话自己的标签，不擅自提升为公共标签。
- 旧进行中、待验收、已验收记录进入对应的兼容展示；没有来源状态时明确显示未指定，不虚构调研、开发或默认阶段。旧“进行中 / 尚未执行”记录在重新可靠核对后允许选择初始自定义状态，不要求先产生执行或验收。
- 不因迁移补发完成事件、补造验收、自动选择下一状态，或自动执行积压任务。
- 保存现有可读取的人工记录，不宣称能还原旧版从未保存的全部历史。
- 不因定位变化改包名、插件身份、数据库目录或 profile 绑定。产品名称是否调整另议，本期沿用会话仪表板。
- 迁移应原子完成，失败保留原数据；事先提供正确备份说明。旧版拒绝读取无法理解的新格式，不以直接拷贝活跃 SQLite 主文件作为降级方式。

### 10.2 第三方接口和独立自动化插件

上一版公开 API v1 与自动化按固定三状态、会话标签及项目归属工作。`0.3.0` 已采用 API v2，**明确拒绝 v1**；新产品状态不能直接塞进原字段并声称兼容。

- v2 区分 `placement` 的 builtin/custom/unset、最近内置执行处置、本轮冻结来源与人工决定；不能把自定义“完成”映射成人工已验收。准确参数与接口名见[扩展 API](<EXTENSION-API.md>)。
- 区分项目公共标签、会话自身标签和用于展示的合并标签。已有规则的标签匹配含义保持不变；升级不自动扩大范围，新范围需要用户明确配置。本轮独立自动化仅提供会话自身标签范围，尚不提供项目公共/合并标签规则入口。
- 阶段验收或转入自定义状态不触发下一轮执行，也不赋予扩展修改核心状态的权限。
- 新阶段、新轮次、跨项目和成员重建后，旧提醒/报告不能当作当前结果；来源不可用或接口不兼容时明确停止受影响功能。
- 独立自动化仍默认关闭；保留现有授权和本地能力边界，不新增自动验收、命令执行或外部发送。
- 若不能提供旧扩展可正确理解的数据，应明确拒绝不兼容调用，不能把未知状态当作进行中或空结果。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |

| A14 | 选好去向后收到同轮重复完成 | 不被拉回待验收，不重复生成历史 |
