# 会话仪表板 · Session Dashboard

[English](<README.en.md>)

在 DSH 中按项目组织会话：项目、标签和状态决定「这件事属于哪里、现在处在哪一步」，执行事实与人工验收保持分离。加入项目不会复制聊天、创建 Agent 或开始执行。

## 安装与打开

需要 Node `>=22.13.0`。声明的 DSH 支持范围是 `0.2.0-rc.1`、`0.2.0-rc.2`、`0.2.1-alpha.1` 到 `0.2.1-alpha.4`、`0.2.1-rc.1` 到 `0.2.1-rc.3`（共 9 个精确版本，见 `package.json`）。

从 GitHub Release 安装预构建包（附件名不带版本，`latest/download` 地址长期有效）：

```sh
dsh plugin --profile web add https://github.com/lemonel/dsh-session-dashboard/releases/latest/download/hsx-dsh-session-dashboard.tgz
```

把 `web` 换成目标 profile。安装后在 GUI 的**插件**页面启用 `@hsx/dsh-session-dashboard` bundle，按提示重载或重启，再打开与「插件」同层级的**仪表板**。不同 profile 的数据库互相独立；安装到另一个 profile 不会更新当前 GUI。构建或打包成功不等于当前 GUI 已部署。

源码构建是备选方式，在本目录执行：

```sh
npm ci --prefer-offline --no-audit --no-fund
npm test
npm run check:package
npm pack
```

包内是运行产物、安装配置、SVG 图标和用户文档，不需要 TypeScript 加载器。

## 首次使用

1. 在项目总览点虚线的**新建项目**建立第一个项目。项目就是内置标签组「项目」的一个值。
2. 新建会话时先选工作区：创建空白会话后立即加入当前项目，并在原生 iframe 预览中打开，第一条消息可以在预览里发送。同一工作区里未开始的空白会话会被复用；若它已属于别的项目，卡片会移动到当前项目而不是重复创建。
3. 已有会话可以从原生侧栏的插件入口加入项目，或拖到项目卡片上；项目卡会话标题左侧的拖动把手只用于在项目之间移动。
4. 点会话标题在浮窗里预览对话（只读，不启动或恢复 Agent）；可全屏、可并排打开第二个会话，关闭后保留有限时间的缓存。需要核对完整事实时，从行菜单打开**会话详情**。
5. 未归入任何项目的会话收在页面底部的**未归属会话**区块；**已归档会话**单独成区，两者都仍属于仪表板。

## 项目、标签与顺序

- 一个会话最多属于一个项目；项目可以包含来自不同工作区的会话。
- 标签组是一套枚举，**每个会话在同一组里最多一个值**；未分组的标签视为一个隐式组。项目自身的公共标签挂在项目这个值上，会话行显示「项目公共 + 会话自身」的合并结果。
- 点右上角「更多操作 → 分类与排列」管理状态、标签组和标签。管理面板默认只显示每类有多少组、多少值，点标题才展开编辑。
- 状态、标签组和标签都支持自定义顺序：行内 ↑/↓ 即保存，顺序属于看板数据，不改变会话内容。
- 项目组是内置组，只能增删/改名它的值（也就是项目），不能删除组本身。

## 状态、执行与验收

- 状态是看板唯一的工作分类：内置的进行中/待确认/待验收/已验收，加上看板全局的自定义状态；颜色和顺序都可配置。
- 执行事实单独显示：被停止、中断或失败的会话按「已停止」「已中断」「失败」展示，不再算作进行中；「需我操作」是从待回答、待授权、阻塞、暂停、失败等事实派生的标记。
- 待验收只能在完整结束后进入；验收必须由你确认，并且绑定当前执行轮次、来源与看板修订。会话在验收前变化时，确认框会说明原因并保留你的选择，不会静默绑定到新一轮。
- 行内状态条可以直接改自定义状态；运行中的会话要等本轮结束。会话详情只保留行上做不到的事：一句话进展、来源核对和执行记录。

## 找到需要处理的会话

右上角的**筛选**是一个通用选择器，按「状态 / 项目 / 各标签组 / 未分组标签」逐行列出可选值，并显示全局计数：

- 普通点击只保留该维度内的这个值；再次点击唯一已选值则取消。
- 按住 **Shift** 点击可在同一维度内多选：组内是「或」，不同维度之间是「且」。
- 触发器显示当前生效值数量；「清除所有筛选」一次复位。
- 筛选同时收窄项目卡片内的会话、未归属区块和已归档区块；计数覆盖所有未归档会话，不随选择变化。
- 筛选只是视图，不写入任何数据，也不改变项目顺序或展开状态。

## 核对、冲突与安全

- 改名、进展和分类都按修订号提交；其他窗口先改过时，你的输入会保留，并提示重新载入，不会覆盖新数据。
- 服务重载、成员身份变化或轮次变化会让旧操作失效，界面说明原因，不自动重试或自动验收。
- 仪表板归档只把卡片从日常视图收起，不改变 DSH 宿主归档状态，也不停止 Agent。宿主归档与看板归档是两件事。
- 进入会话、预览会话和详情操作都不会替你回答、授权或恢复 Goal。

## 归档、数据与升级

- 看板数据保存在目标 profile 的 `data/session-dashboard/dashboard.sqlite`。可在插件配置里用 `dataDir` 指定其他目录，但数据库仍与 profile 绑定。
- 当前看板 schema 为 **11**：项目是内置标签组的值，标签是唯一基础，运行时/API 仍以只读投影提供 `projects` 与 `projectId`。
- 打开 `user_version` 为 `8`、`9` 或 `10` 的旧库时，会在同一事务内升级到 11；更早的库必须先用 `≤0.6.7` 打开升级。升级前建议停止写入者，并备份完整 SQLite 文件（含 `-wal` / `-shm`）。
- 迁移是单向的：旧版本插件不能读取新库。升级失败会保留原库并报错，不会静默清空。

## 可选扩展

核心可以单独使用。扩展有两类：

- **DSH 槽位扩展**：通过 DSH 插件系统加载，向工具栏、卡片徽标、单会话操作等槽位添加内容，见[扩展 API](<docs/EXTENSION-API.md>)（API v2）。
- **仪表板自有扩展**：放在数据目录的 `extensions/` 下，由仪表板自己的加载器读取，能力必须在清单里声明，见[扩展加载器](<docs/EXTENSIONS.md>)。

扩展只能只读查询会话并补读变化，不能任意修改核心状态；未声明的能力不会被授予。

同工作区的 `@hsx/dsh-session-dashboard-automation@0.2.0` 仍声明核心 `^0.3.0`，尚未随 0.7.0 更新，因此**当前版本不要与它混用**；需要自动化时请等它发布匹配核心范围的版本。

## 兼容与验证状态

- 本轮本机验证（2026-10-25，Linux x64 / Node 22.23.1 / Chrome 150）：严格类型检查、构建、570 项 Node 回归、61 项 Chrome 交互测试和包内容检查通过。
- 9 个声明支持的 DSH 版本由 CI 兼容矩阵在 Node 22/24 上逐版本安装、构建和运行；该矩阵是发布前的门禁，本机没有逐版本重跑，云端结果以实际 CI 记录为准。
- Windows、macOS、arm64 未在本机实测；CI 配置覆盖三种 GitHub 托管 runner，但只有真实运行记录才能作为对应平台通过的证据。
- 安装生效、GitHub 发布和 npm 发布是不同步骤；本仓库只通过版本标签触发 GitHub Release，不自动发布 npm。

## 开发

```sh
npm run typecheck
npm run build          # tsc + esbuild，产物在 lib/
npm test               # 先构建，再跑 Node 回归
npm run test:browser   # 真实 Chrome 交互与持久化
npm run check:package  # 打包内容、入口、locale、API 契约
npm run test:surface   # 宿主接口面检查
npm run test:matrix -- --browser   # 隔离目录逐版本安装 SDK
npm run verify:clean   # 删除产物后从源码完整重建
npm run verify:install -- /absolute/path/package.tgz
```

业务源码是严格 TypeScript，按 `src/backend`、`src/frontend`、`src/shared` 分层；构建与测试脚本保留手写 JavaScript；`lib/` 是生成产物，不提交 Git。
